и контрольный navigation без cookie. Реальные пользовательские cookies
не использовались и значения идентификаторов не сохранялись.

navigation без общей cookie:       100 мс

featured bestsellers с cookie:   12134 мс (до заголовков 12110 мс)
navigation с общей cookie:       11934 мс

Запросы одной сессии сериализуются на сервере: два тяжёлых запроса
каталога заставляют быстрый navigation ждать около 12 секунд.
Контрольный запрос другой сессии проходит за 100 мс. Это воспроизводит
наблюдаемую на скриншоте очередь и указывает на блокировку PHP-сессии.
Основное время уходит в ожидание HTTP-ответа, не в передачу тела.

OPTIONS с посторонним Origin получил 204; локальный обновлённый index.php
возвращает для него 403. Следовательно, активный удалённый entrypoint
не соответствует локальной исправленной версии (выкладка/OPcache/маршрутизация
требуют проверки). Сборка dist сама по себе не обновляет PHP на сервере.
Гостевой GET user вернул 401 за 61 мс; показанный на скриншоте 404 user
в этой отдельной анонимной сессии не воспроизведён.

ОБНОВЛЕНИЕ: ПОДГРУЗКА НОВИНОК И БЕСТСЕЛЛЕРОВ ПО 10

Первый запрос каждой карусели теперь содержит limit=10. Следующие десять
товаров запрашиваются при приближении к концу списка либо кнопкой
«Показать ещё». RTK Query хранит страницы вместе, объединяет одновременные
запросы одной страницы и сохраняет уже загруженные карточки при ошибке.
Повтор загрузки продолжает с прежнего указателя. Поиск использует первую
страницу бестселлеров без загрузки остальных товаров.

API catalog/featured теперь по умолчанию отдаёт десять карточек и
pagination: {limit, hasMore, nextCursor}. Следующий запрос передаёт cursor.
Bitrix выбирает ограниченную порцию кандидатов, продолжая по SORT/ID
или DATE_CREATE/ID. Цены, остатки и свойства подгружаются только для этой
порции; вся подборка для каждой страницы не обходится. Окно новинок
фиксируется на момент первой страницы. Неактивные товары и позиции
без фото, цены или доступного остатка не попадают в результат.
За запрос проверяется не более 200 кандидатов, поэтому при длинном
участке недоступных товаров возможна неполная/пустая страница с hasMore.

Проверка в браузере на локальном PHP: оба блока сначала показывают десять
карточек, после прокрутки двадцать; положение прокрутки сохраняется.
PHP FeaturedPaginationTest: 69 успешных проверок, включая обход до конца,
отсутствие дублей, совпадение сортировки, вставку перед указателем,
неверные указатели, пустой каталог и ограничение объёма обработки.

Дополнительный диагностический замер живого API с limit=10, запросы
запущены параллельно с одной отдельной анонимной cookie:
